# Frozen records. Checked by tools/check_standard.py.
#
# A version-history entry for a released revision is the record of what that
# revision changed. It is not edited afterwards, for the same reason a
# published tag never moves. The newest row stays a working draft until its
# revision is tagged, at which point the release checklist pins it here.
#
# This check is not allowlistable. Changing a frozen record means editing this
# manifest in the same commit, which makes the change a deliberate, reviewable
# act rather than a silent one. If you are doing that, say why in the reason
# field and record the decision in the documentation-conflicts register.
#
# Format, fields separated by ::
#   file    :: <repo-relative path> :: <sha256 of the file> :: <reason>
#   row     :: <repo-relative path> :: <line prefix> :: <sha256 of the stripped line> :: <reason>
#   section :: <repo-relative path> :: <heading prefix> :: <sha256 of the section> :: <reason>
#
# A row prefix must match exactly one line in the file, and a section prefix
# exactly one heading. A section runs from its heading to the next heading of
# the same or a higher level; trailing blank lines and rules are not part of it. Recompute hashes with
#   python3 tools/check_standard.py --frozen-hashes
# which prints this manifest with current values and writes nothing.
